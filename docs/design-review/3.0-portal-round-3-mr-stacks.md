## Must-fix: none blocking. One must land in the port, before flashing.

1. **Our own retry can erase the refusal streak.**
   - `g_lastReason` is sticky, and `setupNoteReason` samples it on every `wifiEnsure()` call.
   - Every 12 s, `WiFi.disconnect(false)` + `begin` can post STA_DISCONNECTED with ASSOC_LEAVE (8). That is the case I flagged in round 2. Reason 8 is not on the allowlist, so it resets the streak. A wrong password then never reaches 180 s, and the portal never opens by itself.
   - It also blanks `Wrong password?` for a moment on every retry.
   - The host tests can't catch this, because they never run the retry loop.
   - *Fix:* make 8 neutral. It should neither extend nor reset the streak, and it should not overwrite `g_lastReason`. Only 200 and 201 (the network is gone) should reset the streak. Add a host test: 202, 8, 202, 8, … over 200 s must enter. Then confirm on the device by typing a wrong password and waiting 3 min.
