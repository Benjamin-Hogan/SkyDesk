# 12 — Setup portal (3.0, feature 2)

> Audience: agents and humans building 3.0. Council decision:
> `design-review/3.0-feature-council.md`. Pixel layouts: `mockups/portal_screen.py` (device
> screens) and `mockups/portal/index.html` (the phone page, served byte-for-byte by the
> firmware). Status: **in review** (Mr Stacks, 3 rounds, before any firmware UI). Rounds: `design-review/3.0-portal-round-*`.

## What it is
Today, WiFi, location and time zone are compiled in (`secrets.h`). A wrong WiFi password,
or a new router, means a USB re-flash. The serial link is the only way to see why.

The setup portal lets an iPhone fix all of that. SkyDesk becomes its own WiFi hotspot, and the
phone's camera joins it from a QR code. A page opens by itself (the captive-portal sheet) with
four fields: **WiFi**, **location**, **time zone** and **facing**. Save → SkyDesk restarts and
joins the new network.

It is also the **recovery path**. If SkyDesk can see your network but can't get onto it, it
offers the portal on its own.

## Why not phone GPS and compass
iOS Safari gives Geolocation and DeviceOrientation only to secure (HTTPS) pages. The portal is
`http://192.168.4.1` inside the captive-portal sheet, which is not secure. So location is typed
or pasted, and facing is picked. (Council, both agents independently.)

## Modes
The portal is a **separate boot mode**. There is no TLS, no ADS-B and no radar, so its RAM
(softAP + DNSServer + the core's synchronous `WebServer`, about 25–30 KB) never competes with
TLS. The normal boot pays 0 bytes.

1. **Entering.** An NVS flag `setupReq` is set, then the device reboots. `setup()` sees the flag,
   **clears it first** (so a crash or power cut comes back in normal mode), and runs the portal.
2. **Ways in:**
   - Settings → **Phone setup** (a new menu row).
   - The boot error screen's **Set up from phone** button, shown from the first failed join.
   - **Automatically**, only when *your network is visible* but joining has failed for
     `SETUP_AUTO_S` (3 min): a wrong password, or MAC filtering.
     - "Visible" comes from the WiFi **disconnect reason**, not a scan. AUTH_FAIL /
       AUTH_EXPIRE / 4-way- or handshake-timeout mean visible and refusing; NO_AP_FOUND (201)
       means not visible (`setupReasonVisible`).
     - If the network isn't visible (router off, power cut, a 5 GHz-only network), SkyDesk
       keeps retrying and never strands itself in setup mode.
     - With no SSID configured at all, it enters at once.
     - The same rule applies after a mid-run drop, not only at boot.
   - The boot screen's hint uses the same reason: `Wrong password?` or
     `Not found - 2.4 GHz only?` (`setupReasonWords`), each only when true.
3. **Leaving:**
   - Save → the settings are written as **one NVS commit** → then "Saved" on both screens →
     reboot after 3 s.
   - **Cancel** on the device fires on a **1 s hold** (a fill shows progress), then reboots with
     nothing changed. The button is ≥ 36 px (R2-9).
   - With no phone joined: `SETUP_IDLE_S` (15 min) → reboot, nothing changed. After an
     **automatic** entry it's `SETUP_AUTO_IDLE_S` (5 min), and a touch extends it. A refusing
     router that recovers is back within about 8 min, not 18.
   - A joined session with no request for `SETUP_SESSION_S` (30 min) → reboot (abandoned).
4. The portal runs at **full backlight** whatever night-dim says: a dimmed QR scans worse.

## The hotspot
- **SSID:** `SkyDesk-Setup-XXXX`, where XXXX is the last 4 hex digits of the MAC, so two
  SkyDesks never collide.
- **Password:** WPA2, 8 **lowercase letters without i/l/o** (`SETUP_PW_ALPHABET`, 23⁸). That's
  one iPhone keyboard page: no Shift, no `123`.
  - It is generated once per device (`esp_random`) and kept in NVS, so iOS's remembered
    network keeps working next time. A new password each session would make a remembered join
    fail with "Incorrect password".
  - It is shown on screen and inside the QR. The alphabet contains none of `\ ; , : "`, so
    it never needs QR escaping (host-tested).
- **QR:** `WIFI:T:WPA;S:<ssid>;P:<pass>;;`. Version 4, ECC M, 33 modules at 4 px = 132 px, with a
  4-module quiet zone. The iPhone camera app offers "Join network". Generated by Nayuki's
  qrcodegen (C in firmware, the same algorithm in Python for the mock), so the pixels match.
- **Addresses:** IP 192.168.4.1. The DNS server answers **every** name with that IP.
- **Captive-portal probes** (`/hotspot-detect.html`, `/generate_204`, `/ncsi.txt`,
  `/connecttest.txt`, any unknown path) return the page, so iOS opens its sheet by itself.
  The address is printed on screen as a fallback.

## The phone page (`mockups/portal/index.html`)
One self-contained page: no external files, about 9 KB, served from flash.

**The firmware inlines the state** into the page it serves (it replaces the `/*STATE*/` marker
with `var S={...}`), so there's no second request that could fail.
- If the state is ever missing, the page says `Can't read SkyDesk's settings` with a Reload
  button, and never shows sample data.
- The sample data is used only when the file is opened from disk or from `127.0.0.1` (the design
  review); the device is always `192.168.4.1`.
- The `[http]` log never prints the POST body.

The sections:

1. **WiFi network.**
   - A list from a scan (strongest first, mesh duplicates collapsed, 2.4 GHz only: `SkyDesk
     sees 2.4 GHz networks only.`), plus "Other…" for a hidden SSID.
   - **Scan again** reloads `/?scan=1`. With no networks found, the name box shows at once and
     the note says so.
   - Password field with Show/Hide (44 pt). Leaving it blank keeps the saved password only when
     the SSID is the saved one. **The saved password is never sent back to the page.**
2. **Location.** One text box.
   - It accepts decimal (`33.35280, -111.78900`) or degrees-minutes-seconds. Any symbol
     separates, so the iPhone's curly quotes (`33°21’10”N`) work too, host-tested with the
     owner's string. A hint: `Decimal, or like 33 21 10 N 111 47 20 W`.
   - A live line under it, with distances one decimal under 10 mi:
     - Inside `SETUP_GATE_MI`: `Reads as 33.35280, -111.78900 · 0.0 mi from the map center`
       (OK green).
     - Inside `SETUP_RADAR_GATE_MI` (1 mi): `… 0.4 mi from Gilbert, AZ. Too far for the street
       map, which will show planes without streets. Radar and weather work.`
     - Beyond it: `… The map and radar are built for Gilbert, AZ: weather and plane cards will
       use your location, the map shows planes without streets, and the radar is off.` If the
       Name still says the build place, it is cleared.
   - A time-zone hint from the longitude (`Looks like Eastern.`) when it disagrees with the pick.
   - An optional **Name** field (20 characters) appears on the boot screen.
   - "Reset to the map center" restores the build location.
3. **Time zone.** A short list: Arizona (no DST, the default), Pacific, Mountain, Central,
   Eastern, Alaska, Hawaii. Each maps to a POSIX TZ string in the firmware.
4. **Facing.** 8 compass buttons plus a degrees box, the same value as the device's Facing dial
   (which stays).
5. **Save.** The response page says what happens next: "SkyDesk is restarting and joining
   *HomeNet*. You can close this page."

Validation happens in both the page and the firmware:
- SSID: 1–32 bytes. Password: empty (keep) or 8–63.
- Latitude −90…90, longitude −180…180.
- Facing 0–359. The time zone must be from the list.

The firmware re-checks everything; the page is only a convenience.

## Device screens (`mockups/portal_screen.py`)
- **Settings menu:** four rows (Facing, Dim at night, **Phone setup**, Calibrate touch) at 36 px
  each, plus Done.
- **Portal, waiting:**
  - QR on the left (132 px plus the quiet zone, dark on white). On the right, `ON YOUR PHONE`
    and 4 numbered steps: `Open Camera` / `Aim at the code` / `Tap Join` / `Page opens`.
  - Below them: the hotspot name, and the password (fsb9, big: people type it when the QR
    fails).
  - At the bottom: `or open 192.168.4.1`, **Hold to cancel** (112 × 36, fills while held), and
    `closes in 14 min` in glcd.
- **Portal, phone joined** (a station associated, but no `GET /` yet): `Phone joined · No page?
  Open Safari to 192.168.4.1`.
- **Portal, page open** (`GET /` served): `Page open · Finish on your phone`.
- **Portal, saved:** `Saved · Restarting, joining "HomeNet"`. A long SSID falls back to `your
  WiFi`.
- **Boot error:** it gains a **Set up from phone** button (220 × 36). Its hint line is the
  reason words.
- **Automatic entry:** the portal title says why, `Can't join "HomeNet"` in WARN. It falls back
  to `Can't join your WiFi` when the SSID doesn't fit.
- **Off-gate map** (beyond `SETUP_GATE_MI`): rings, you, planes and the strip, but no streets,
  towns or airports. `(c) OSM` becomes `No streets here - built for Gilbert, AZ` in glcd.
- **Off-radar-gate radar** (beyond `SETUP_RADAR_GATE_MI`): a plain message, `The radar map is
  built for Gilbert, AZ · Your location is 2,127 mi away · Weather and planes use your
  location`. The weather rain cue is off.

## Settings and the observer
- **NVS** (namespace `skydesk`), with `secrets.h` as the defaults:
  - `wSsid`, `wPass`, `apPw` (the hotspot password)
  - `lat`, `lon`, `place`, `elevFt`
  - `tz`
  - `setupReq`
- **Observer** (`include/observer.h`): `obs()` returns lat/lon/elevation/place.
  - The build location comes from `OBS_LAT`/`OBS_LON` (what the basemaps were built for).
  - A saved location overrides it.
  - `obsInGate()` = within `SETUP_GATE_MI` (0.1 mi, about 2 px at the 5 mi zoom) of the build
    location.
  - `obsInRadarGate()` = within `SETUP_RADAR_GATE_MI` (1 mi, about 2 radar pixels).
  - Every `OBS_LAT`/`OBS_LON`/`OBS_ELEV_FT` in firmware becomes `obs().…`. The host tests use
    the build location.
- **Elevation:** after a move, it comes from Open-Meteo's `elevation` field (already in the
  forecast response), saved once. Until then it's the build elevation.
- **Time zone:** `configTzTime(settings().tz)`.

## RAM and flash
- **Normal boot:** +0 heap. The observer/settings strings add about 150 B static.
- **Setup boot:** about 30 KB heap. No sprites except the TFT itself, no net task.
- **Flash:** the page about 8 KB, WebServer + DNSServer about 30 KB, qrcodegen about 6 KB.

## Tests (host)
- **Location parser:** decimal, DMS with the owner's exact string, **the same string with iPhone
  curly quotes**, N/S/E/W signs, commas and spaces; rejects out-of-range and junk.
- **Gates:** the distance from the build location; the street gate and the radar gate (0.4 mi =
  no streets, radar kept).
- **Form validation:** SSID/password lengths, keep-password-when-blank, facing range, TZ list.
- **Auto-entry rule:** by disconnect reason. AUTH_FAIL / handshake timeout for ≥ 3 min →
  enter; NO_AP_FOUND → never; no SSID → immediate. The boot words follow the reason.
- **QR:** the firmware's qrcodegen output for a fixed string equals the Python mock's matrix
  (a fixture).
- **AP password:** 8 lowercase letters, none of i/l/o, and the alphabet never needs QR
  escaping.

## Device checks (human)
1. Settings → Phone setup. The iPhone camera joins from the QR, and the sheet opens by itself.
2. Change nothing, then Save: it reboots and rejoins.
3. Type a wrong password, then Save: it can't join, and after 3 min the portal comes back on its
   own.
4. Paste the DMS location. The page shows `0.0 mi from the map centre`.
5. 8-bit heap after a normal boot: unchanged from Today's Sky (about 70 KB free).

## Round 2 decisions (binding; they override any wording above)
- **"Visible" is an allowlist.** Only AUTH_EXPIRE 2, 4WAY_HANDSHAKE_TIMEOUT 15, AUTH_FAIL 202 and
  HANDSHAKE_TIMEOUT 204 count as "the network is there and refusing".
  - BEACON_TIMEOUT 200, CONNECTION_FAIL 205, ASSOC_LEAVE 8, NO_AP_FOUND 201 and all others don't.
  - The auto-entry timer is a **refusal streak** (`setupNoteReason`/`setupRefusingMs`), which
    any non-refusing reason resets. Host-tested: 8/200/201/205 never enter.
- **ASCII on the device.** Name and SSID pass through `setupAsciiFold()` before any device font
  draws them (curly quotes, dashes and Latin-1 letters folded; others become `?`).
  - An SSID that isn't plain ASCII shows as `your WiFi` in titles.
  - The Name's 20-character limit is checked after folding.
- **Boot error:** the retry countdown sits at the right of the failed row (`12 s`), and the next
  line is only the reason's words.
- **"Page open"** comes from the page's own `POST /opened` after it renders, not from the first
  `GET` (iOS's probe fetches the page too).
- **Cancel hold:** the fill starts on touch-down; dropouts under 150 ms don't reset it. Released
  early, the label flashes `Keep holding` for 1.5 s. Once a phone has joined, `closes in N min`
  is hidden (the 30-min session rule applies).
- **Location wording:** `Everything works here.` / `Works here: … Off here: …`.
  - A cleared Name gets the placeholder `Name this place`.
  - The time-zone hint appears only inside the US; Arizona is checked first (Yuma).
- **Scan again** fetches `/scan` (JSON) and rebuilds only the network list; every other edit
  stays.
- **Settings:** 4 rows × 36 px at y 34/74/114/154, and Done is 100 × 36 at y 198. The hold-3-s
  hint line is gone (calibration is a row; the hold still works).
- **Hotspot password alphabet:** `abcdefghjkmnpqstuwxyz`. `r` and `v` are dropped (`rn`/`m`,
  `vv`/`w` in fsb9).
- **Parsers:** the page sends **decimal** lat/lon (already parsed); the firmware only range-checks
  them. The two parsers therefore can't disagree on Save. The C parser is for host tests and any
  future typed input on the device.
- **Neutral reasons (round 3 M1).** Only 200/201 (the network is gone) reset the refusal streak;
  the allowlisted refusals extend it. Every other reason is **neutral**: it neither extends nor
  resets the streak and doesn't replace the shown reason. That includes ASSOC_LEAVE 8, which our
  own 12 s retry's `WiFi.disconnect()` reports. Host test: 202/8 alternating over 200 s opens the
  portal.
- **Name:** folded inside `setupValidate` (not only by the server).
- **Far wording:** it names what still works: the plane map without streets. Coming back near
  home with an empty Name restores the home name.

## Firmware review fixes (two independent reviewers, before the first flash)
- **Save rules** are pure and host-tested: `setupApplySave()` (keep the password, location at the
  build vs custom, elevation re-learned on a move, Name folded, an empty Name at home → the home
  name). A Name saved at the build location now shows.
- **Strict input:** `setupParseNumber()` (no `nan`, no trailing junk). `setupValidate` rejects NaN.
  `setupCfgSane()` guards the NVS blob at boot (a bad one → the build defaults). The Open-Meteo
  elevation is range-checked.
- **Script-safe JSON:** `setupJsonEscape` also escapes `<` `>` `&`, so a neighbour's SSID
  `</script>…` can't end the inlined state.
- **Refusal streak (reviewer R1):** fed from the WiFi event under a spinlock; continuous (gaps ≤
  30 s); needs a password-type refusal (15/202/204). AUTH_EXPIRE 2 alone (weak signal, busy AP)
  never opens the portal. One refusal followed by silence doesn't either.
- **Probes don't keep a session alive.** Only `/`, `/scan`, `/save` and `/opened` refresh it.
  An **automatic** portal ends after `SETUP_AUTO_CAP_S` (10 min) unless the page is open (an
  iPhone may auto-rejoin the remembered hotspot).
- **Scan again works inside the iOS sheet** (its hostname is captive.apple.com). It has an 8 s
  timeout, and the scan dwell is 80 ms per channel.
- **Other fixes:**
  - The time-zone default follows `NTP_TZ`.
  - The boot title falls back to `your WiFi` when it would reach `retry N s`.
  - An empty Name shows the coordinates only.
